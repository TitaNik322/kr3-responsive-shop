# KeyboardShop

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

## Описание

Многостраничный магазин механических и оптических клавиатур. За основу взят [проект КР №1](https://github.com/TitaNik322/kr1-html-css-shop). В новой версии адаптированы навигация, главный экран, каталог, карточки товаров, формы и таблицы.

Использованы HTML5, CSS3 и JavaScript без Bootstrap, сторонних UI-библиотек и сборщика. Каталог находится в HTML; скрипт дополняет его фильтрацией и сортировкой.

## Адаптивные решения

- На всех страницах добавлен `viewport`. Файл `responsive.css` подключён после `style.css`.
- Использован Mobile First: базовая версия для телефона расширяется через `min-width`.
- Сетка товаров: одна колонка на телефоне, две с 640 px, три с 1024 px. В каталоге с боковым фильтром три колонки появляются с 1280 px.
- Навигация на телефоне раскрывается через `details`; с 768 px ссылки идут в строку. Шапка закрепляется на широких экранах.
- Hero и страница товара с 768 px переходят к двум колонкам.
- Фильтры на телефоне сворачиваются, а с 1024 px становятся боковой колонкой.
- Формы идут в одну колонку; с 640 px — в две. Поля не ниже 48 px, кнопки не ниже 44 px.
- Строки таблицы на телефоне превращаются в карточки «параметр — значение»; с 640 px возвращается табличное представление. Данные не дублируются.
- Изображения ограничены шириной контейнера. Применены `picture`, WebP, `srcset`, `sizes`, JPEG fallback, размеры `width`/`height` и отложенная загрузка карточек.
- Подвал прижат к нижнему краю коротких страниц через Flexbox: `body` имеет `min-height: 100dvh`, `main` занимает свободное место. На длинных страницах подвал следует после содержимого и не перекрывает его.

## Доступность

- На каждой странице один `h1` и один `main`, используются семантические элементы.
- Добавлены skip-link, видимый `:focus-visible`, `aria-current` и осмысленные `alt`.
- Поля связаны с `label`; применены `required`, `type="email"`, `pattern`, `minlength` и `autocomplete`.
- Ошибки связаны с полями через `aria-describedby`. `aria-invalid` появляется после ошибки и очищается при исправлении.
- Результаты проверки формы выводятся через `role="status"`.
- Диалог открывается через `showModal()`, удерживает Tab/Shift+Tab внутри, закрывается Escape, кнопкой или нажатием на фон. После закрытия фокус возвращается на исходную кнопку.
- Мобильное меню поддерживает клавиатуру и Escape. Навигация остаётся доступной без JavaScript.
- Учтено `prefers-reduced-motion`: плавная прокрутка и переходы отключаются по предпочтению пользователя.

## Lighthouse

Отчёты сохранены в `lighthouse/`. Категория — **Accessibility**, мобильная эмуляция **375 × 812 px**, проверка через локальный HTTP-сервер.

Актуальная проверка: **11 ноября 2026 года, Lighthouse 13.6.0**.

| Страница | Accessibility | Отчёт |
| --- | ---: | --- |
| Главная | 100/100 | [HTML](lighthouse/index-accessibility.html) |
| Каталог | 100/100 | [HTML](lighthouse/catalog-accessibility.html) |
| Товар | 100/100 | [HTML](lighthouse/product-accessibility.html) |
| Заявка | 100/100 | [HTML](lighthouse/order-accessibility.html) |
| Контакты | 100/100 | [HTML](lighthouse/contacts-accessibility.html) |

Lighthouse дополняет проверку клавиатуры, фокуса и удобства интерфейса, но не заменяет её. Аудит выполнялся локально, без тестового workflow в GitHub.

## Проверенные ширины

Основная проверка адаптивности: **360, 375, 430, 768, 1024 и 1440 px**. После обновления оформления отдельно просмотрены версии 360 и 1440 px и расположение подвала на всех семи страницах при увеличенной области просмотра 2880 × 1800 px.

## Самостоятельные доработки

- Мобильное меню с клавиатурным управлением и закрытием при нажатии снаружи.
- Сворачиваемые фильтры, проверка диапазона цены, сброс, сортировка и понятный пустой результат.
- Мобильное карточное представление таблицы с сохранением её HTML-семантики.
- Несколько размеров фотографий и WebP-версии; варианты изображения hero через `picture`.
- Доступный диалог с явным управлением фокусом и очисткой ошибок при повторном открытии.
- Прижатый к низу подвал, согласованное оформление страниц и фотографии на светлом фоне.

## Запуск и формы

Можно открыть `index.html` в браузере. Для локального HTTP-просмотра из корня проекта:

```sh
python -m http.server 8765
```

Адрес: `http://localhost:8765`. Установка зависимостей не нужна.

Backend к формам не подключён: они проверяют введённые данные в браузере, но не создают заказ на сервере и ничего не сохраняют. Сообщение об успешной проверке не означает отправку заявки. Контактные значения статические.
