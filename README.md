# KeyboardShop — контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».
Автор: **Ситников Александр Андреевич, ЭФБО-01-25**.

Адаптация собственного магазина клавиатур из КР №1. Сохранены три товара, их страницы, описания, характеристики и БЭМ-блоки. Bootstrap, сборщик и сторонние библиотеки не используются.

## Запуск

Откройте `index.html` в браузере либо запустите из корня проекта:

```sh
python -m http.server 8765
```

Адрес: http://localhost:8765. Установка зависимостей не нужна. Формы работают в демонстрационном режиме: проверяют данные локально, не отправляют и не сохраняют их.

## Структура

- `index.html` — главная, hero, преимущества, коллекция;
- `catalog.html` — каталог, фильтры и сортировка;
- `product.html`, `product-1.html`, `product-2.html` — исходные модели, адаптивная таблица и быстрая заявка;
- `order.html` — форма заявки; `contacts.html` — контакты и форма обратной связи;
- `css/style.css` — оформление, переменные, БЭМ-блоки;
- `css/responsive.css` — Mobile First и медиазапросы;
- `js/main.js` — небольшие улучшения нативных меню, модального окна, форм и каталога;
- `images/` — локальные фотографии и оптимизированные WebP-версии.

## Адаптивные решения и самостоятельные доработки

- Базовая сетка в одну колонку; с 640 px — две, с 1024 px — три. Каталог с боковой колонкой получает три карточки с 1280 px.
- Мобильное меню на нативном `details`: клавиатура, Escape, закрытие при нажатии снаружи. На широком экране — строка ссылок.
- Сворачиваемые мобильные фильтры, на desktop — боковая колонка; работающие фильтры по типу и цене, сброс, пустой результат и сортировка. Исходные карточки находятся в HTML.
- Hero и страница товара меняются с одной на две колонки. Контейнеры используют `min()`, заголовки — `clamp()`, сетки — `minmax(0, 1fr)`.
- `picture` переключает hero между 640 и 1200 px. Карточки используют WebP, `srcset`, `sizes`, JPEG fallback, `loading=lazy`, размеры изображений. Маленький оригинал Logitech не увеличивается искусственно.
- Таблица на телефоне отображается карточками «параметр — значение» без дублирования данных; с 640 px возвращается табличное представление.
- Форма в одну колонку на телефоне и в две с 640 px. Поля не меньше 48 px, кнопки не меньше 44 px.
- Нативный `dialog` с ограничением высоты и внутренней прокруткой; он располагается поверх закреплённой шапки.

## Доступность

Один `h1` на странице, логичные заголовки, семантические landmarks, `aria-current`, осмысленные `alt`, связанные `label`, видимый фокус и skip-link. Учитывается `prefers-reduced-motion`. Формы используют HTML-валидацию, сообщения результата доступны через `role=status`. Клавиатурный аудит выполнен: Tab/Shift+Tab остаются в диалоге, Escape закрывает его, фокус возвращается на исходную кнопку. Текстовые ошибки связаны с полями через aria-describedby; aria-invalid ставится только после ошибки и очищается при исправлении и повторном открытии формы. Меню и каталог доступны также без JavaScript.
